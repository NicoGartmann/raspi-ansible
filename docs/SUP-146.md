## 1. Anpassungen im `raspi-ansible`-Repository

### 1.1 `--env-file` in `roles/docker_compose/tasks/main.yml` und `playbooks/update.yml`
Da die Compose-Dateien künftig in Themen-Unterordnern (`connectivity/adguard.yml`, `documents/docker-compose.yml` usw.) liegen, sucht Docker Compose die `.env`-Datei standardmäßig im jeweiligen Unterordner statt unter `/opt/services/.env`.

In [`roles/docker_compose/tasks/main.yml`](../roles/docker_compose/tasks/main.yml) und [`playbooks/update.yml`](../playbooks/update.yml) wird der Aufruf um `--env-file` ergänzt:

```yaml
# Pull:
cmd: "docker compose --env-file {{ compose_repo_dest | default('/opt/services') }}/.env -f {{ item }} pull"

# Up:
cmd: "docker compose --env-file {{ compose_repo_dest | default('/opt/services') }}/.env -f {{ item }} up -d"
```

## 2. Migrations-Checkliste für die Zielgeräte

### 2.1 Migration auf `raspberrypi`
Da auf `raspberrypi` die Verzeichnisse bereits unter `/opt/adguard`, `/opt/nginx-proxy-manager` und `/mnt/drive/paperless` liegen, müssen **keine** Bestandsdaten verschoben werden. Lediglich die laufenden Container des alten monolithischen Stacks (`/opt/services/docker-compose.yml`) werden vor dem Rollout sauber gestoppt, damit die neuen Einzel-Stacks (`adguard`, `proxy`, `twingate`, `documents`, `samba`, `monitoring-agent`) die Container-Namen und Ports übernehmen können:

1. **Alten monolithischen Compose-Stack auf `raspberrypi` stoppen (Daten bleiben unberührt)**:
   ```bash
   ssh nico@192.168.178.10 "cd /opt/services && sudo docker compose down"
   ```
2. **Neue Themen-Stacks über Ansible ausrollen**:
   ```bash
   ansible-playbook playbooks/docker-compose.yml --limit raspberrypi --ask-vault-pass
   ```

---

### 2.2 Migration auf `parents_pi`
Auf `parents_pi` liefen die Container bisher über `/home/pi/docker-conf` mit relativen Pfaden (`./adguard/data`, `./adguard/config`, `./plex/config`, `./overseerr/config`). Vor dem ersten Ansible-Lauf von `docker-compose.yml` werden die bestehenden Konfigurationsdaten einmalig nach `/opt/...` verschoben:

1. **Alten Compose-Stack unter `/home/pi/docker-conf` stoppen**:
   ```bash
   ssh nico@192.168.178.46 "cd /home/pi/docker-conf && sudo docker compose down"
   ```
2. **Zielverzeichnisse unter `/opt` anlegen und Bestandsdaten verschieben**:
   ```bash
   ssh nico@192.168.178.46 "
     sudo mkdir -p /opt/adguard /opt/plex /opt/overseerr &&
     sudo mv /home/pi/docker-conf/adguard/data /opt/adguard/work &&
     sudo mv /home/pi/docker-conf/adguard/config /opt/adguard/conf &&
     sudo mv /home/pi/docker-conf/plex/config/* /opt/plex/ &&
     sudo mv /home/pi/docker-conf/overseerr/config/* /opt/overseerr/ &&
     sudo chown -R 1000:1000 /opt/plex /opt/overseerr
   "
   ```
   > [!NOTE]
   > Beachte bei AdGuard die Umbenennung der Unterordner von `data` → `work` und `config` → `conf`, damit die Ordnerstruktur unter `/opt/adguard` auf beiden Pis identisch ist.
   > Prüfe in `/opt/adguard/conf/AdGuardHome.yaml` kurz, dass unter `http: address:` `0.0.0.0:80` eingetragen ist, damit das Bridge-Port-Mapping (`8080:80` bzw. `ADGUARD_WEB_PORT:80`) auf Anhieb greift.
3. **Neue Themen-Stacks über Ansible ausrollen**:
   ```bash
   ansible-playbook playbooks/docker-compose.yml --limit parents_pi --ask-vault-pass
   ```
4. **Aufräumen nach erfolgreichem Funktionstest (Plex, Overseerr, AdGuard, Samba)**:
   * Sobald alle Dienste unter `/opt/services` sauber laufen, kann `/home/pi/docker-conf` auf `parents_pi` gelöscht und das GitHub-Repository `docker-conf` archiviert werden.
